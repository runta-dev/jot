# R27 distinguish prototype improvement from final delivery

Preregistered before this comparison. User explicitly permits temporary rough edges while progressing toward the full goal. Earlier 4/4 and14/16 gates remain useful final-quality requirements, but holding the live prototype forever on a known unusable ASCII baseline does not advance the product. This protocol introduces a separate, explicitly weaker prototype-promotion decision; it does NOT redefine or relax final goal completion. No comparator or specialized handler permitted.

Evaluate the frozen eight two-turn general-chat-v1 conversations with (A) current ASCII baseline and (B) full-continuation morphological word decoder with subtitle corpus, no branching/chunks/editor/verifier/tree modes. Own actual generated histories. Same cases,40 words vs280 characters are disclosed different output budgets (both bounded prototype decoders);180s per turn, word method500k input ceiling. Save full traces and costs. Each case evaluated once; dataset is development, not held-out. No threshold or prompt changes during run.

Prototype promotion requires >=8/16 clearly adequate B turns AND at least6 more adequate turns than A, no fabricated drawer answer, no new provider/API secret exposure, working cancellation/streaming and retained history in live browser before presenting. Every failure is retained. Failing the gate means no switch. Passing permits only a labeled experimental general-chat implementation with no claim of reliability or final completion. Final goal still requires broad fresh multi-turn validation, stability and acceptable latency/cost beyond these small dev cases. Keep current UI minimal, no research comparator UI.

Human adequacy rubric frozen from general-chat-v1; classify borderline separately. No automatic Jev judge decides passes. Surface style alone is not failure; false content, missing explicit requirement, incomprehensible grammar, or empty/loop output are failures. Story may be simple, but must actually be a story; happier revision must plausibly improve the previous generated ending. Record judgments in one table, with explanations.
